# AGENTS.md

## Cursor Cloud specific instructions

This repo (`forge` / AetherForge) is a Rust workspace (`Cargo.toml`, `crates/`, `tests/golden_harness`) plus a macOS-only Swift app (`macos/`, `Package.swift`). Cloud agents run on **Linux**, so the relevant scope is the Rust workspace + golden harness. Darwin is the canonical platform.

### Services / components
- **`aether-daemon`** — the app. TCP JSON-lines server on `127.0.0.1:7433`. Run with `cargo run -p aether-daemon`. See `docs/DAEMON_IPC.md`.
- **`golden-harness`** (`tests/golden_harness`) — 61-task acceptance eval. Run with `cargo run -p golden-harness`.
- **macOS Swift app** (`swift build` / `swift run AetherForgeApp` / `scripts/build-ffi.sh`) — **cannot run on Linux** (no Swift toolchain here); skip it.

### Build / test / lint / run (standard commands live in `README.md`, `.github/workflows/ci.yml`, `docs/LINUX_CI.md`)
- Build: `cargo build --workspace` · Tests: `cargo test --workspace`.
- Static lint gate (the only one CI runs): `scripts/scan-mcp-allowlist.sh`. CI does **not** run `cargo clippy` or `cargo fmt`.
- Run app: `cargo run -p aether-daemon`.

### Non-obvious caveats
- **Toolchain:** a transitive dep needs Rust edition2024, so **Rust ≥ 1.85 is required** (build fails on older). The base image's default `rustup` toolchain may be pinned to an old version; the update script runs `rustup default stable`.
- **Golden harness on default Linux scores 48/61 (36 hard-green / 12 soft-green) — this is correct, not a regression.** `FS-02`/`SB-01`/`DIST-01` require Darwin `sandbox-exec`/codesign; `ROUT-01`, `MEM-01`, `GRAPH-01`, `GRAPH-02`, `LOOP-02`, `PLAN-01`, `LOOP-04`, and `INGEST-01` require Darwin/Ollama and print `FAIL-CLOSED`; `MCP-01`/`MCP-02` currently fail the pinned entry-script hash because `npm install -g @modelcontextprotocol/server-filesystem` drifted upstream — re-pin only after reviewing the new build. With local Ollama and a matching MCP pin the score is 58/61. The ten newest tasks — `CHECK-02`, `GATE-03`, `RED-02` (wave 1), `LOOP-05`, `READ-01`, `REPLY-01`, `PLAN-02` (wave 2), `MEM-04`, `COMPACT-02` and `GATE-04` (wave 3) — are deterministic (no model, no network) and pass on both platforms. Last measured Linux run: `34758427779` at **48/61** (36 hard / 12 soft), where all four wave-2 tasks (`LOOP-05`, `READ-01`, `REPLY-01`, `PLAN-02`) plus wave 3's `MEM-04` and `COMPACT-02` passed hard and `GATE-04` passed soft. The one regression this branch produced is worth remembering: `SUB-01` failed in run `34719007714` because the P1-6 preview marker lengthened every distilled line until the last file's *name* fell off the 2 000-char cap — `preview_budget` now derives the quote length from the file count, because a summary that drops a path hides a file the parent could have asked for. See `docs/LINUX_CI.md`.
- **Session logs:** every structured-loop execution path (`run_task`, automation triggers, gateway inbound) appends a JSONL transcript under `AETHER_SESSION_LOG_DIR` (default `~/.aether/sessions`) via `aether_daemon::session_log`. `SESS-01` overrides that env var for its own duration only.
- **Git tool children use a fixed local identity** injected by `ProductionSandbox`; host/global git identity is not inherited.
- **Daemon IPC auth:** on non-macOS, auth is optional (no Keychain) unless `AETHER_DAEMON_AUTH_TOKEN` is set. `ping` never needs auth.
- **Loop plan JSON field is `"action"`**, not `"tool"` (one `README.md` snippet is stale). After an `fs_write`, the verify shell blocks `done` until both a `verify_contains` and a lint step have succeeded. A known-good hello-world plan:
  `{"loop":[{"action":"fs_write","path":"hello.txt","content":"forge"},{"action":"verify_contains","path":"hello.txt","text":"forge"},{"action":"python_lint","source":"def ok():\n    return 1\n"},{"action":"done"}]}`
- **A written `.py` artifact must be linted *as that file*** (CHECK-02). `python_lint` compiles source quoted in the plan, so it proves nothing about anything on disk; for every path ending in `.py` that the plan wrote, the gate also requires a successful `python_lint_file` **on that same path** before `done`. A known-good Python plan:
  `{"loop":[{"action":"fs_write","path":"hello.py","content":"def ok():\n    return 1\n"},{"action":"verify_contains","path":"hello.py","text":"def ok"},{"action":"python_lint_file","path":"hello.py"},{"action":"done"}]}`
  There is no `nc` on the box; drive the daemon via a small `python3` socket client (or `cargo run -p aether-daemon --example stream_client`, which needs Ollama).
- **Gates can be dark-launched, and promotion is a measurement** (GATE-04). `AETHER_GATE_MODE=<gate>:log` makes a *blocking* gate record the denial it would have made and allow the call, so a new or retuned rule can run against real traffic before it is allowed to break anything. Three properties are not optional: only names in `DARK_LAUNCHABLE_GATES` can be set to `log` (a typo is refused with the real list, one bad entry invalidates the whole spec); `hook.output_redaction` is refused outright, because logging instead of redacting *is* the leak; and an absent, empty or unparsable spec enforces everything — a configuration error must never be what turns a gate off. `GateLedger` pairs each decision with a `CorpusLabel`, so `GateSummary` reports false positives and misses per gate and `ready_to_enforce` is the promotion criterion (`observed == 0` is **not** clean). Wired at the two hook deny sites and at `admit_plan_against_observations`; `drain_gate_hits()` is the flush point for an audit writer, since `aether-permissions` owns the hash-chained `audit_log` insert and this must not reimplement it. Anything that mutates `AETHER_GATE_MODE` needs an RAII restore guard and belongs at the end of the harness run.
- **Compaction is a trust-boundary crossing** (COMPACT-02). Reach for `compact_turns_guarded` with a `CompactPolicy`, not bare `compact_turns`, whenever history is compacted: roles in `keep_verbatim_roles` (`system`, `policy`) are never handed to the summarizer, a summary derived from untrusted turns inherits `trust="untrusted"` in `render()`, `reanchor_preamble` is re-emitted at the top of the compacted context, and `compacted_observation(&result, iteration)` is the observation a replan must be re-admitted against — otherwise an injection that survives only inside the summary becomes invisible to the correlation gate. Nothing in the daemon calls compaction yet, so the guarded API and that re-admission seam are the contract a caller has to use; the gap is recorded in `docs/REVIEW_FABLE51_HARNESS.md`.
- **Retrieved memory is filtered at both ends** (MEM-04). At write time `filter_memory_write` redacts never-store material — secrets, payment-card and financial-account numbers, government IDs, immigration status — **even when the turn asks for it**, and only a user-authored chunk may be `stated`: an assistant proposal is stored `inferred`, tool output `derived`, with the kind encoded in the chunk id (`{session}::t{n}::{actor}-{kind}`; a legacy `::turn` id still parses as user/stated). At read time `admit_retrieved_memory` drops any chunk carrying imperative or privilege-escalating language, and the prompt states how many were dropped — a silent drop is indistinguishable from an empty store. The wrapper also states that **the current request overrides retrieved memory when they conflict**, so a stale stored preference cannot outrank the person typing.
- **A plan can discover the workspace, and the planner is told what exists** (PLAN-02). `{"action":"fs_list","path":"<relative dir>"}` lists one directory (omit `path` for the workspace root): sorted, directories suffixed `/`, an empty directory reported as `0 entries` rather than an error, and a cut listing reports its bound. It is a *read* — same `PreToolUse` hook, same `read` grant, same remedy-bearing denial. Before the model plans, `task_runner::planner_context` appends a volatile capability block (connected MCP servers, installed skills, the workspace top level) after the stable `build_nl_plan_prompt` prefix, so prefix-cache reuse is unaffected; absence is stated as `none` plus "do not emit one", never omitted. A goal containing "list" now requires an `fs_list` step.
- **A finished run's answer is `LoopRunResult.reply`, not `.summary`** (REPLY-01). `summary` is the last observation — for a plan ending in `done` that is the literal `"plan complete"`. `reply` is an `aether_core::FinalReply { text, artifacts }`: validated before it is emitted (non-empty, not a bare status token, names every path the run wrote, ≤ 2 000 chars), emitted as a `FinalReply` stream event immediately before `Done`, mapped to the `final_reply` wire event with the artifacts to present, and logged to the session transcript. Show `reply.text`; present `reply.artifacts`.
- **`fs_read` takes an optional character window** (READ-01): `{"action":"fs_read","path":"big.txt","offset":9900,"limit":400}`. A read that is cut says so — the observation carries `[truncated …]` with the file's true character count, how much was omitted, and the literal next page — and the default cut is **from the middle**, so the tail (`return`, `main`) survives. An offset past the end is a *failed* observation naming the real size, never an empty string. Never treat a marker as "not present": page instead. The same rule holds for the other two bounded surfaces, memory injection (`[memory truncated: N of M hits shown …]`) and the subagent preview (`[preview: 200 of N chars …]`).
- **Tool failures carry their remedy** (LOOP-05): `aether_core::ToolError` renders `reason | remedy: … | constraint: {…} | retryable: yes|no`, and the reason from the producing site is always the leading substring, so `contains("Write denied")`-style assertions and audit rows keep matching. `run_structured_with_replan` classifies **before** spending one of its `MAX_LOOP_REPLANS` attempts: a failure no plan can repair (missing grant, unconnected MCP server, pin violation, exhausted budget) returns immediately with `replans == 0` and the remedy, instead of burning the budget and surfacing a model-availability error. It also looks *past* the failing step: `mcp_call`/`skill_execute` record a failed observation and the loop continues, so the `verify_contains` that finally trips is a symptom — the root cause is what gets classified.
- **MCP filesystem server** is installed at `/usr/local/lib/node_modules/...` (an auto-discovered candidate path); the harness resolves node via `which node`. `MCP-01` passes on Linux once installed.
- **System deps:** building needs `pkg-config` + `libssl-dev` (openssl). `BYOK` env vars (`AETHER_BYOK_PROVIDER`) fail-closed on Linux — do not set them.
- **Subagent PR-creation gap (lesson learned):** a `best-of-n-runner` subagent dispatched to wire the undo/checkpoint IPC methods into the SwiftUI app (`DaemonClient.swift`, new `SafetyModel.swift`/`SafetyView.swift`, `AetherForgeApp.swift`) reported it had no `ManagePullRequest` tool access, so it could not open its own PR. Its commit ended up carried into `main` as part of an unrelated PR's base rather than reviewed on its own — a real process gap, not a content problem (the code was manually reviewed after the fact and confirmed to build clean on Darwin CI: `main` @ `51658d0`, run `30838281310`, `Build complete!` with only a pre-existing non-sendable-capture warning). **Do not assume a dispatched subagent can create its own PR.** Either verify it has that tool before relying on it, or have the orchestrating agent create the PR itself once the subagent's branch is ready — do not just declare success because the subagent says it committed and pushed.
